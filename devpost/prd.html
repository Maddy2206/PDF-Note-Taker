PDF Note taker

Product Requirements (visual companion). Canonical source: devpost/prd.md. Draws on scope.md.

A web app where a student reads a PDF in one pane and builds handwritten-style, editable notes in the other. Highlights flow into the notes automatically. Landing page is built last and is not part of this first pass.

The core journey

Highlighted boxes are the heart: highlight-to-note (must-keep) and diagram import (in the demo).

Screens

Dashboard

  • Card grid of boards
  • Name + last reopened
  • Create, rename, delete
  • Click opens saved state

Board workspace

  • PDF | draggable divider | notes
  • Close either pane
  • Notes toolbar, lined/blank paper

Behaviors and acceptance criteria

must-keepHighlight to handwritten note
  • Selecting text shows a popout: color, font, Export to board.
  • Export adds the exact selected words, in the chosen handwritten font, at the next free spot.
  • Color highlight stays on the PDF.
  • Note item can be edited, moved, deleted.
demoDiagram import
  • Diagram select tool draws a dotted boundary around a region.
  • Confirming imports it as an image into the notes.
  • Moves and resizes like handwritten text.
Create board and upload
  • Asks for a name and a PDF.
  • Non-PDF is rejected with a message; no board created.
  • Success lands in the workspace with the PDF shown.
Dashboard cards
  • Card shows name and last-reopened time.
  • Click restores the board exactly.
  • Rename works; delete asks for confirmation.
Split workspace
  • Divider drags left and right.
  • Close the PDF pane (notes only) or notes pane (PDF only), and bring it back.
Notes tools
  • Pen, colors, shapes and other Excalidraw-like tools; undo/redo; export.
  • Lined or blank paper, user's choice.
  • Everything selectable, movable, deletable.
Save, resume, download
  • Reopen restores PDF position, highlights, notes, divider.
  • Download produces a PDF showing handwriting, diagrams and drawings.

States and boundaries

  • Empty Dashboard: prompt to create the first board.
  • Wrong file type: rejected automatically with a message.
  • Empty notes: blank or lined paper with tools visible.
  • Scanned PDF (assumption): text highlight can't work, so the user sees a message; diagram select still works.
  • Persistence: boards, PDFs, highlights and notes survive between sessions. Per browser or per account is a spec decision.

Decisions you made

  • Name "PDF Note taker"; functional pages first, landing page last.
  • Exact highlighted words, no AI rewriting.
  • Default AI-app styling for the app chrome (no specific direction).
  • Download as PDF; lined/blank paper left to the user; PDF-only upload; rename and delete boards.
  • Everything in scope is "now"; time is not a constraint.

Deferred / non-goals

  • Marketing landing page (built last).
  • Accounts, sharing, collaboration.
  • AI summarizing; non-PDF files.
